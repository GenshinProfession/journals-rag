# 硕博论文自动生成系统 — 需求文档

## 一、产品概述

开发一个根据用户的学历背景、学科要求、学术idea自动生成标准硕博论文的AI系统。

## 二、面向用户的核心需求

代写用户选择学校（马来西亚、泰国、澳门、韩国）→ 输入专业（自动匹配专业方向的skills）→ 确定论文主题 → 上传一份标准参考论文并由 AI 审核质量 → 上传/整理文献（支持文件夹分类编辑）→ RAG 入库 → 直接输出带该学校标准（格式、理论深度、内容深度、数据分析）的毕业论文。

系统不做多租户，固定两种角色：管理员和代写。管理员使用后台入口，代写用户使用前台入口，部署时通过两个 Nginx 代理入口切分。

### 目标学科（现阶段）

| 大类 | 具体学科 | 研究方法特点 |
|------|----------|-------------|
| **文科** | 艺术学、哲学、历史学 | 理论+历史文本深厚，需田野调查，访谈分析（如扎根法），强理论综述 |
| **社会科学** | 新闻传播学、管理学、经济学 | 实证/实验法研究，生成CSV原始量表数据（五级/七级Likert量表），SPSS/Stata运算 |

### 学位层次

| 层次 | 产出 | 字数要求 |
|------|------|----------|
| 本科 | 毕业论文 + 格式规范 | ≥10万字 |
| 硕士 | 毕业论文 + 格式规范 | ≥20万字 |
| 博士 | 毕业论文 + 课程PPT + 格式规范 | ≥30万字 |

## 三、用户画像与使用场景

- **目标使用者**：平台内部/合作的代写账号，服务对象是在上述国家/地区留学的中国学生
- **核心痛点**：不熟悉当地格式规范、学术写作能力不足、数据分析能力不足
- **使用时机**：开题后拿到导师反馈、论文写作中期、定稿前格式调整

## 四、专业-技能自动匹配

系统需维护「专业 → 研究方向 → 所需技能」的知识图谱：

- **艺术学** → 艺术理论、美学分析、艺术史梳理、田野调查、图像学分析
- **哲学** → 概念分析、逻辑论证、哲学史梳理、文本诠释、比较哲学
- **历史学** → 史料考证、口述史方法、历史比较法、档案研究、计量史学
- **新闻传播学** → 内容分析、框架分析、问卷调查、深度访谈、网络文本分析
- **管理学** → 量表设计（Likert 5/7级）、SPSS回归分析、结构方程模型(SEM)、案例研究
- **经济学** → 计量模型、面板数据分析、Stata操作、DID/RDD因果推断

## 五、文献管理模块

- 文件夹分类（按主题/章节/年份等多维度）
- 标准参考论文审核：用户先上传一份对应主题的高质量参考论文，AI 判断主题相关性、论文形式和学术质量，审核通过后才允许后续 RAG 入库
- 文献元数据提取（标题、作者、年份、摘要、DOI）
- RAG 入库：AI 辅助语义切割，用户可人工拆分、合并、删除、改标签，确认后再写入 PostgreSQL pgvector
- 自动生成参考文献列表（APA/Harvard/Chicago/GB7714 等格式）
- 文献与论文章节的引用映射（哪篇文献支撑了哪个段落）

## 六、研究方法模块

### 文科路径
理论综述生成 → 田野调查方案设计 → 访谈提纲生成 → 访谈数据编码（扎根法三级编码：开放式编码、主轴式编码、选择性编码）→ 理论饱和度检验

### 社科路径
研究假设提出 → 量表自动生成（维度设计、题项编写、信效度检验逻辑）→ 生成模拟CSV原始数据 → SPSS/Stata分析（描述统计、Cronbach's α信度、KMO/Bartlett效度、相关分析、回归分析、中介/调节效应检验）

## 七、论文输出（按学校定制）

每所学校配置一份论文模板，包含：页边距、行距、字号、字体、章节结构（必选章节）、引用格式、理论深度占比、查重规避策略。

## 八、学位层次差异化

| 维度 | 本科 | 硕士 | 博士 |
|------|------|------|------|
| 字数 | ≥10万 | ≥20万 | ≥30万 |
| 理论深度 | 理论概述+应用 | 理论比较+批判分析 | 理论创新+体系构建 |
| 研究方法 | 基础描述统计 | 推断统计+回归 | 高级计量/质性分析 |
| 创新点 | 1个 | 2-3个 | 3-5个系统性创新 |
| 额外产出 | — | — | 课程PPT |

## 九、Agent架构（多Agent协作）

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ 参考审核Agent │ →  │ RAG切割Agent │ →  │  选题Agent   │
│ (质量门槛)    │    │ (入库前处理) │    │ (开题+大纲)  │
└──────────────┘    └──────────────┘    └──────────────┘
       ↓                   ↓                   ↓
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  文献Agent   │ →  │  写作Agent   │ →  │  审校Agent   │
│ (综述+引用)  │    │ (章节撰写)   │    │ (查重+逻辑)  │
└──────────────┘    └──────────────┘    └──────────────┘
```

## 十、关键决策（已确认）

| 决策项 | 结论 |
|--------|------|
| **撰写语言** | 默认中文输出；全文翻译为独立功能，另外开发 |
| **导师反馈回路** | ✅ 支持 — 用户中途修改章节后，系统自动调整后续章节一致性 |
| **查重与降重** | ✅ 支持 — 内置查重检测和降重改写功能 |
| **部署方式** | ✅ 服务器部署优先 — PostgreSQL + pgvector，不再按本地优先设计 |
| **角色体系** | ✅ 固定两类角色 — 管理员 admin、代写 writer |
| **前后台入口** | ✅ 后台和前台分离 — 两个 Nginx 代理入口 |
| **充值扣费** | ✅ 管理员人工充值；AI 调用后查中转站 token 消耗并按平台价格扣费 |
| **模型选择** | ✅ 代写用户按场景自选模型；管理员维护模型目录和价格 |
| **标准参考论文审核** | ✅ RAG 前置门槛 — 用户先上传标准参考论文，AI 审核通过后才允许入库 |
| **输出格式** | ✅ Word(.docx) + LaTeX 两者都支持 |
| **RAG入库方式** | ✅ 支持 — AI 预切割 + 人工确认 + pgvector 入库 |
