新的产品结构：模板区 + 正文区

模板区负责人工资料和学校固定格式；正文区负责 AI 写作、引用、段落微调和最终导出。

关键修正：论文标题、论文主题、正文方向要分开

论文标题应来自模板区的标题字段；论文主题是给 AI 写作时使用的研究方向、对象、方法、范围，不能只让用户填一个“题目”就直接生成大纲。

大纲生成输入不再只有“论文主题”

  • 论文标题：模板区已填好的正式标题。
  • 论文主题：研究对象、方法、范围、实验/设计目标。
  • 模板正文槽位：哪些章节属于正文区，哪些是参考文献和致谢。
  • 可用文献：上传或检索后的文献，决定正文引用和参考文献列表。

1 绪论

1.1 研究背景与意义

温湿度监测在农业生产、仓储管理和智能家居等场景中具有重要意义。传统人工记录方式存在实时性不足、数据连续性差和人工成本较高等问题，因此有必要设计一种低成本、可扩展、能够稳定运行的智能监测系统[1]。

本课题以 STM32 微控制器为核心，结合温湿度传感器、显示模块和无线通信模块，实现环境数据采集、展示与上传。

1.2 国内外研究现状

现有温湿度监测系统逐渐从单点采集转向网络化、平台化和智能化管理，相关研究主要集中在传感器精度、低功耗通信和远程数据管理等方向[2]。

2 系统总体方案设计

2.1 系统功能需求分析

系统需要完成温湿度数据采集、阈值报警、实时显示和远程传输等功能，并保证硬件结构简洁、软件逻辑清晰。

后续执行路线

1. 模板解析输出改成两大区

结构 DSL 直接产出 template_zone 与 body_zone。模板区只收集字段，正文区才进入 AI 写作。

2. 正文格式完整分析

正文区需要独立抽取 body、heading1-4、figure、table、equation、reference、acknowledgement 的格式。

3. 大纲生成输入重构

使用正式标题 + 研究主题 + 模板正文槽位 + 文献约束，而不是只传一个 topic。

4. 文档内编辑交互

段落点击后浮出工具条；左侧树只做跳转、状态、章节批量操作，不再左右对照编辑。

5. 长生成与记忆系统

生成过程拆成项目记忆、章节记忆、小节生成、段落续写和一致性检查，支持长论文不断点、不丢上下文。

参考文献脚注 / 交叉引用调研结论

  • 当前本地实现只是普通文本标注和最后的参考文献列表，没有真正建立 Word 脚注、尾注或交叉引用字段。
  • python-docx 官方 API 对脚注/尾注支持不足；要做原生脚注需要注入 footnotes.xml、关系文件和 w:footnoteReference。
  • 如果学校要求的是 GB/T 7714 的正文 [1] 标注，应渲染为小号右上角上标，并做“内部超链接 + bookmark”，让上标 [1] 跳到最后参考文献。
  • 如果学校要求页脚脚注，则需要实现 OOXML 后处理，不能只靠 python-docx 普通段落 API。
  • 当前 test-local 的 bookmark id 固定为 0，必须改成递增唯一 id；内部链接应使用 w:anchor，而不是把 #ref 当外部 relationship。正文 run 需要设置 vertAlign=superscript 和更小字号。
